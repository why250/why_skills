# /distill — 对话沉淀路由器

从当前对话提取值得复用的知识，选择合适的作用域和存储位置，再按用户授权落盘。同内容只维护一个权威来源，其他位置需要时链接引用。

本 skill 可安装在宿主支持的用户级 skills 目录，供不同项目调用。安装位置只存放 skill 自身；沉淀产物的位置由当前任务决定，不以安装目录为项目根，也不把各项目知识累积到本 skill 内。

当活动项目就是 `why_skills` 时，先读取 `docs/skill-lifecycle.md` 与 `docs/conventions.md`；新建 Skill 前先查重，优先更新已有权威来源。

## 1. 确定项目和作用域

先做有限的只读探查，得到足以路由的信息：

- 优先使用用户指定的目标；否则结合当前工作目录、对话涉及的文件和仓库边界确定活动项目。单仓多项目时，定位实际涉及的子项目，不把仓库根自动当作所有产物的归属。
- 读取目标位置适用的 `AGENTS.md` 或其他宿主指令，以及与候选主题直接相关的现有代码、skills、规则和文档。遵守其目录、命名和维护约定。
- 从当前宿主提供的技能目录、配置或已有结构识别可用的项目级/用户级 skills、规则与记忆位置。不要假定某个编辑器、隐藏目录、文件名或外部 skill 必然存在。
- 只检查相关目录和已知配置，不遍历用户主目录、不扫描历史 transcript，不把其他项目的知识带入当前项目。

区分两种作用域：

| 作用域 | 适用内容 | 位置选择 |
|--------|----------|----------|
| 项目级（默认） | 依赖本项目代码、架构、领域约定或环境的知识 | 当前项目或所属子项目的现有权威位置 |
| 用户级 | 脱离当前项目仍成立的通用流程，或用户明确要求跨项目生效的偏好 | 宿主已识别的用户级 skills、指令或记忆位置 |

“可以复用”不等于已获准全局生效。建议用户级沉淀时，在分类表中标明作用域；先去除项目名、绝对路径、内部地址、凭据和其他私有细节，将必要输入改为参数或发现步骤。项目特有配置留在项目内。

若项目归属、宿主支持或目标位置仍不清楚，只询问影响落盘的最少信息；同时继续提炼不依赖答案的候选。没有项目上下文时，不猜测项目路径，也不默认写入全局位置。

## 2. 提取高信号候选

从当前可见对话和相关已验证产物中提取：

| 候选类型 | 信号 |
|----------|------|
| 流程 | 多步、可重复、有清晰触发条件 |
| 决策 | 重要取舍及理由、约束和影响；不以模块数量作硬门槛 |
| 踩坑 | 症状 → 根因 → 修复，已验证 |
| 可代码化 | 可测、可 CLI、重复执行 |

**不沉淀**：本轮 diff 清单、临时进度、已存在的重复内容、未经验证的猜测。没有高信号候选时直接说明，不为完成流程新建文件。

优先将可自动化、可验证的行为落实为代码或工具检查，避免只写一条要求人反复执行的规则。多步操作选 skill，持续生效的短约束选 rule，设计解释选文档，重要取舍选 ADR，局部经验选项目记忆。代码不能替代必要的设计理由；它们记录不同信息时可分别保存。

## 3. 给出具体分类与落点

先输出分类表。路径应来自实际探查，而不是照搬示例；新位置标注“建议新建”，未确定位置写“待确定”，不把占位符当成可写路径。

```markdown
| # | 类型 | 作用域 | 提炼内容 | 具体路径 | 操作 | 理由 |
|---|------|--------|----------|----------|------|------|
| 1 | skill / rule / 代码 / doc / ADR / memory | 项目 / 用户 | … | … | 新建 / 更新 | … |
| — | 不写 | — | … | — | 跳过 | 已有 / 临时 / 未验证 |
```

仅说“沉淀”或“固化本轮”时，展示表格并等待用户选择后再写。用户可以全选、选子集、改分类/路径或全部跳过。

如果当前会话中用户已明确授权了内容和目标范围（例如“把这个流程直接更新到用户级的某个 skill”或“按项目约定直接沉淀，不用逐项问”），简要列出落点后直接执行授权部分，不重复确认。未授权的全局扩展或范围外修改仍留作建议。修改本 skill 的请求属于技能编辑任务，不套用此处的沉淀确认流程。

## 4. 按授权项落盘

### 位置路由

优先顺序：**用户明确指定的位置 → 目标范围内已有权威文件 → 项目/宿主约定 → 提议最小新位置**。已有内容先读再更新，不另建平行的文档树。

| 类型 | 路由方式 | 无现成位置时 |
|------|----------|--------------|
| 代码 | 所属模块、现有工具或脚本目录 | 在相关项目内建议最小实现位置，不为沉淀另开包 |
| skill | 更新已有同主题 skill；新建时按作用域选择宿主支持的 skills 目录 | 先确定宿主可发现的位置，不自行创造隐藏目录 |
| rule | 现有项目指令文件或宿主规则机制；尽量缩小生效范围 | 建议宿主支持的项目指令位置；不要把普通文档声称为自动生效规则 |
| doc | 项目现有设计文档或主题文档 | 在已有文档目录建议一个主题文件；没有目录时再提议最小位置 |
| ADR | 现有决策记录目录、编号与模板 | 在项目文档体系中建议单条决策记录，不强制新建整套体系 |
| memory | 宿主实际支持的项目记忆，或项目已采用的经验文件 | 可建议普通经验文档，但说明不会因此自动加载为记忆 |

### 内容要求

- **代码**：实现最小可运行改动，采用与风险匹配的验证。可由接口、帮助或错误信息表达的内容不另写长篇说明。
- **skill**：保留清晰触发条件和最终可行流程，参数化环境差异。`SKILL.md` 包含 YAML `name`、`description`；细节确有需要时放 `references/`，可复用脚本放 `scripts/`。遵循目标宿主已有技能格式。
- **rule**：短、可执行，限制到相关项目或路径；有路径匹配机制时使用它。不要将项目特例升级为所有项目的全局纪律。
- **doc**：记录结构、约定与理由，避免复述代码和操作流水账。
- **ADR**：记录背景、决定、备选项及后果。优先现有模板；仅在相关 ADR skill 可用时使用它，不依赖固定名称或路径。没有模板时用这些字段写一条自足记录。
- **memory**：使用实际日期，短条目记录适用环境及“症状 → 根因 → 已验证修复”；可附权威来源链接，长设计放文档。

落盘前检查重复和冲突；用已验证结论更新过时内容，无法判断冲突时指出差异，不静默覆盖。一次性小经验可追加到现有文件，不为了形式创建独立 skill。

## 5. 验证与回报

检查实际改动与授权一致，路径和引用有效，用户级产物不残留项目私有细节；代码运行适当检查，skill 使用可用的校验工具。普通知识文件以内容和差异检查为主。

简洁回报：

- 已写：类型、作用域、文件链接、提炼内容。
- 未写或待确认：原因及需要补充的信息（有则列出）。
- 验证：做了什么、有哪些实际限制。

## 协作边界

- 若当前环境提供技能编写、ADR 等相关 skill，按需使用；缺失时仍可依靠本流程完成最小沉淀。
- 状态快照、任务交接不属于知识沉淀；不要替代项目已有的 checkpoint/交接流程。
- 本 skill 不要求安装额外工具，也不自动修改宿主配置、复制自身到每个项目或发布产物。
